### Code Editor

Implemented.

Features:

* Monaco Editor integration
* Starter code (classSnippet) loaded from question
* Question-specific code templates

Question execution templates use a placeholder:

```cpp
LECO_USER_CODE
```

During judging:

```text
Code Snippet Template (codeSnippet)
        +
User Class Implementation (classSnippet / user code)
        ↓
Final Compilable Source File
```

`LECO_USER_CODE` is replaced by the user's submitted class/function implementation before compilation.

### Run & Submit Flows

Fully independent — both can be in-flight simultaneously.

Run:

* Sends code to `POST /submissions/run`
* No DB record saved
* Runs against question examples only
* Returns per-example results (input / expected / actual / pass/fail)
* Result shown in "Run result" tab

Submit:

* Sends code to `POST /submissions/submit`
* Submission saved to MongoDB with status PENDING
* Runs against all hidden testcases
* Returns verdict + first failed testcase if WA
* Result shown in "Submit result" tab
* Submission history updated

Both APIs wait synchronously for the worker to finish and return the full result directly. No polling needed.

### Verdicts supported

```
AC  WA  CE  RE  TLE  MLE  SYSTEM_ERROR
```

## Judge System

Implemented.

### Queues (BullMQ + Redis)

Three separate queues:

```
submitQueue   — official submissions, retries 3x with exponential backoff
runQueue      — run jobs, no retry
tcGenQueue    — testcase output generation, retry 2x
```

All jobs carry minimal payloads. Workers load full data from MongoDB.

Workers run in-process alongside the Express server (concurrency: 1 each).

### Docker Execution (`services/dockerJudge.js`)

For each job:

1. Write final source to a temp directory on host
2. Mount temp dir into `gcc:13` Docker container
3. Compile with `g++ -O2`
4. If CE → return immediately
5. For each testcase input → spawn one process (`./solution < input_N.txt`)
6. Collect stdout, detect TLE (timeout), MLE (exit code 137 / OOM kill), RE (non-zero exit)
7. Clean up temp dir

Resource limits per container:

* `--memory=<memoryLimit>m` + `--memory-swap=<memoryLimit>m` (swap disabled)
* `--cpus=1`
* `--network=none`

### submitWorker

1. Load submission + question + testcases from MongoDB
2. Build final source (`codeSnippet` with `LECO_USER_CODE` replaced by user code)
3. Run through Docker
4. Compare each output using question's `comparatorType`
5. Save verdict + executionTime + firstFailedTestCase to submission

### runWorker

1. Load question from MongoDB (template + examples)
2. Build final source
3. Run through Docker against `question.examples`
4. Return per-example results (no DB write)

### tcGenWorker

1. Load question + all testcases from MongoDB
2. Build final source using `officialSolution`
3. Run through Docker (3x time limit for official solution)
4. Save generated outputs back to testcase documents via `bulkWrite`
